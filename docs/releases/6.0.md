# Marque 6.0 — 2026-09-11

## What's new

**Marque has an admin panel.**

Until now it didn't. The entire admin surface across twelve packages was two user
screens in `marque/usarrs` and a taxonomy screen you had no way to reach — the
navigation even rendered an "Admin" link to a route that nothing, anywhere, had
ever registered.

- **`marque/skipper`** (new package) — the admin panel, at `/admin`. It lists the
  admin screens your installed packages provide, grouped, filtered to what the
  logged-in user's role allows. Install it and your existing screens appear; leave
  it out and nothing changes.

- **`marque/ise` is now `marque/deck`** — the shared layout shell. Same package,
  same components, new name and namespace.

## The part that matters beyond this release

Packages now *declare* what they contribute to the interface, rather than the
shell holding a hardcoded list of the packages it knows about.

That list was the real problem. A navigation entry could only be added by editing
and releasing the shell package, and a third-party package could never appear at
all. Now a package registers a screen or a nav entry against `marque/trove` — the
one package every deployment already installs — and whatever renders the interface
picks it up without knowing that package exists.

So a `marque/taxonomy-anime` from someone who isn't us can add an admin screen and
a menu item, and it works. That wasn't possible before, in any form.

**This contract is public API as of this release.** If you're writing a package for
Marque, build against it.

## Who's affected

**Anyone using a frontend package** — `guise`, `disguise`, `usarrs` or `parley`.
They all depend on the layout shell, so the `ise` → `deck` rename ripples through
them. That's why they've gone up a major version: the package you must install has
changed, even though none of their own APIs did.

**Not affected:** an API-only or tracker-only install — `trove`, `threepio`,
`bloodhound`, `hound`, `cennad`, `squidink`, `taxonomy` — has nothing to do here
beyond ordinary updates.

**Your routes are unchanged.** `route('admin.users.index')` and
`route('admin.users.show')` keep their names, paths and components. usarrs still
owns and binds its own admin routes; registering them with the panel only makes
them *discoverable*.

## What you need to do

1. Swap the shell package:

   ```bash
   composer remove marque/ise
   composer require marque/deck:^2.0
   ```

2. Work through the [upgrade guide](../upgrade-guide-ise-to-deck.md) — namespace,
   view namespace, component tags, config file and env var. It's search-and-replace,
   but **two things won't fix themselves**:

   - a published `config/ise.php` in your app (rename it to `config/deck.php`)
   - the `layout` default in a published `guise.php` / `disguise.php` /
     `usarrs.php` / `parley.php`, which still says `ise::layouts.app`

   One trap worth knowing: a search for `ise::` **will not match**
   `<x-ise::button>`, because the hyphen isn't a word character. Replace both
   patterns.

3. Optionally install the panel:

   ```bash
   composer require marque/skipper
   ```

   It appears at `/admin`. With nothing registered it says so plainly rather than
   rendering an empty page.

## Adding your own admin screen

From your package's service provider:

```php
use Marque\Trove\Enums\Role;
use Marque\Trove\Registry\AdminScreen;
use Marque\Trove\Registry\AdminScreenRegistry;

$this->app->make(AdminScreenRegistry::class)->register(new AdminScreen(
    identifier: 'client-whitelist',
    label: 'Client Whitelist',
    component: 'my-package-client-whitelist',
    path: 'admin/clients',
    minimumRole: Role::Moderator,
    group: 'Tracker',
));
```

Your package depends on `marque/trove`, never on skipper. See
[`packages/skipper/README.md`](../../packages/skipper/README.md) and
[`docs/integration.md`](../integration.md) Pattern 5.

## Why the admin panel ships with no new admin features

Deliberately. v1 is the panel and the mechanism, with the three admin surfaces that
already existed moved onto it — nothing new.

Building new admin functionality at the same time would have shaped the extension
point around whatever the first feature happened to need, which is how a panel ends
up shaped like its first tenant. The obvious next one is bloodhound's client
whitelist and blacklist, which today you edit directly in the database.

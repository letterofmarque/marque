# Marque 9.0 — 2026-10-19

**bloodhound 8.0.0 · threepio 4.0.0 · hound 5.0.0 · trove 4.6.0 · usarrs 8.3.0 · marque 1.1.0 · guise 5.2.0 · disguise 5.2.0 · cennad 4.4.0**

## What's new

**Bloodhound credits every announce the moment it arrives, bytes and time alike.**

Until now, seedtime was worked out later from the announce log, and three things that
should have worked together didn't: announces that anti-cheat refused still earned time,
the bytes a `stopped` announce reported were thrown away, and turning the log off made a
rebuild zero everyone. Now each announce is measured once, against the peer's last
announce, and its ledger row records what it earned: bytes up and down, and seconds
seeding or leeching. Every total (per member and per torrent) is a sum of those rows plus
whatever pruning carried forward, so reconcile, rebuild and the audit all agree, and a
prune no longer costs anyone credit.

**The tracker's Redis must persist and never evict.** Every credit is measured against
the peer's last counters, held in Redis. A Redis that forgets them, by restarting without
persistence or evicting keys under memory pressure, would lose credit silently. So
bloodhound now requires `appendonly yes` and `maxmemory-policy noeviction`, checks them,
and in production refuses announces until they're right. `marque:install` checks the same
before it builds a private tracker. If Redis is lost anyway, bloodhound notices and
rebuilds baselines from the ledger.

**Anti-cheat stops refusing legitimate clients.**

- **Location limits replace the connection cap.** A member may seed one torrent from 3
  locations and leech it from 1. A location is an address, or an IPv6 /64. Only a new
  location counts, so a client already in the swarm is never refused for being there.
- **Nothing limits how many torrents an address seeds**, on bloodhound or hound. A member
  can run up to 5 clients on one torrent.
- **A speed over the cap forfeits those bytes** instead of refusing the announce.
- **Seedboxes:** members register theirs, an admin approves them, and announces from an
  approved seedbox are held to a higher cap (10 Gbit/s by default).
- **Members can end their own sessions.** A client restarted with a new peer ID somewhere
  else used to be refused until its old session expired. The member can now end the old
  one from their profile, and the refusal tells them so.

**Every client is announced correctly.** Laravel stripped certain bytes from the ends of
binary info hashes and peer IDs, so about one torrent in twenty could never be announced,
and a peer ID that wasn't text was never recorded. Both trackers now read the raw query
string, and a scrape answers for every torrent it names.

## Also fixed

- **A banned member's API token kept working.** A ban ended web sessions only. With
  usarrs 8.3, the API refuses the token too.
- **The magic-link email said the link lasts 15 minutes.** It lasts as long as your
  password-reset links (60 minutes by default), and now says so.

## Who's affected

**Anyone running bloodhound.** Configure Redis before you upgrade: in production, 8.0
refuses announces until it's durable. Members' limits change as described above, and
over-cap transfers are forfeited rather than refused.

**Anyone running hound.** `ip_limiting.max_per_ip` is replaced by
`max_peers_per_torrent` (10): a cap on one address's peers on one torrent, not across
every torrent.

**Everyone else**: guise, disguise, cennad, usarrs and the installer no longer require
threepio directly (it still arrives through trove), so they install beside threepio 4.
Nothing changes in how they behave, except usarrs' fixes above.

## What you need to do

**Private tracker.** Follow bloodhound's
[upgrade steps](../../packages/bloodhound/README.md#upgrading-from-7x-to-80): make Redis
durable first, update a published config, then upgrade together:

```bash
composer require marque/bloodhound:^8.0 marque/trove:^4.6 marque/usarrs:^8.3 marque/guise:^5.2 -W
```

Add `marque/cennad:^4.4` if you run the API. If your `composer.json` names
`marque/threepio` itself, require `marque/threepio:^4.0` in the same command. Then
`php artisan migrate`, `php artisan bloodhound:check-redis`, delete the old Redis keys
(step 7), and, optionally, run `bloodhound:backfill-ledger` to credit pre-8.0 history its
time. No rebuild is needed.

**Public tracker.**

```bash
composer require marque/hound:^5.0 marque/trove:^4.6 marque/disguise:^5.2 -W
```

Rename `ip_limiting.max_per_ip` to `max_peers_per_torrent` in a published
`config/hound.php`. Then delete the old per-IP Redis sets once, with your tracker's
connection flags and your Redis prefix in place of `marque:`:

```bash
redis-cli --scan --pattern '*marque:ip:*:peers' | xargs -r redis-cli del
```

**Using the members' screens.** usarrs 8.3 adds `/profile/seedboxes`,
`/profile/sessions` and `/admin/seedboxes`, linked from `/profile/stats`. They work
only when bloodhound 8 is installed; without it they answer 404 and nothing links to
them. If you published usarrs' views, re-publish
`profile/stats.blade.php` to get the links.

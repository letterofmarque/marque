# Marque 12.0 — 2026-11-02

**bloodhound 11.1.2 · threepio 4.3.0 · hound 5.3.0**, with the releases on the way:
threepio 4.2.0, bloodhound 10.1.0 and hound 5.2.0 (2026-11-01), bloodhound 10.2.0, 11.0.0,
11.1.0 and 11.1.1 (2026-11-02), then bloodhound 11.1.2 (2026-11-04).

## What's new

**IPv6 peers reach the swarm.** Before threepio 4.2, a peer that announced over IPv6 was
recorded and then left out of every compact peer list, which packed only IPv4 addresses,
and compact is what clients ask for. Behind
Cloudflare, which publishes IPv6 addresses for proxied sites, that could be most of a
tracker's members. IPv6 peers now go out in `peers6` (BEP 7) beside the IPv4 ones in
`peers`.
- A dual-stack client, which announces over IPv4 and IPv6 in turn, is handed out in both
  families in compact responses.
- `ipv4=` and `ipv6=` are honoured: on by default in bloodhound, where the announcer is a
  member and the ledger records what they claimed; off by default in hound, where nobody
  answers for an announce.
- An IPv4 client behind a dual-stack listener (`::ffff:a.b.c.d`) is no longer refused in
  production as "Invalid IP".

**A tracker can take one address family only.** `address_families` in bloodhound and
hound takes `ipv4`, `ipv6` or both (the default). An announce over the family that's off
gets a normal response with no peers and a message the client shows ("This tracker
accepts IPv4 announces only"). It isn't an error, so dual-stack clients carry on over the
other family, and nothing is recorded for it.

**Dual-stack households aren't refused for switching families.** This is bloodhound 11.0,
the major. A house with two leeching clients, one dual-stack and one IPv4-only, used to
have the dual-stack client's IPv6 announces refused as a second location. That case is
now *ambiguous*, and `anti_cheat.ambiguous_locations` decides what happens to it:
- `flag` (the default) accepts it, credits it, and flags its ledger row;
- `refuse` keeps 10.x's behaviour;
- `allow` accepts it without a flag.

bloodhound 11.1 adds the other side of the same house: an IPv4-only client starting
beside a dual-stack one, which before was refused on every try, is ambiguous too. 11.1.1
does the same for a client turning from seeding to leeching beside one, which was refused
for up to an hour. 11.1.2 makes `BLOODHOUND_AMBIGUOUS_LOCATIONS` work on trackers with a
published config, which is every one `marque:install` built. Before it, `refuse` couldn't
be chosen there.

A new daily command, `bloodhound:detect-location-sharing`, reports two patterns of one
account used from more than one place. Operators with better evidence than bloodhound has,
such as their own GeoIP/ASN data, can bind their own `LocationJudge`.

The trade is spelled out in bloodhound's README. Some account sharing looks exactly like a
dual-stack household, and no tracker can tell the two apart. `flag` accepts those cases
with a trace, and the README lists what the detector can't see.

## Who's affected

**Anyone running bloodhound.** Ambiguous locations are accepted and flagged instead of
refused. To keep 10.x's refusals, set `BLOODHOUND_AMBIGUOUS_LOCATIONS=refuse` (on 11.1.2
or later). Coming from Marque 11.0 (bloodhound 10.0), run `php artisan migrate`: 10.1 adds
two nullable columns to `announce_log`.

**Anyone whose app code reads `announce_log` directly** and takes a flagged row with no
baseline (`prior_up` null) for a refusal. From 11.1, an admitted new client's row is
exactly that. Ask `AnnounceLog::refused()` or use the `accepted()` scope.

**Anyone running hound.** Upgrade it with threepio (below). IPv6 peers then start
reaching each other, with nothing to configure.

**Anyone who worked round dual-stack refusals** by raising
`BLOODHOUND_MAX_LEECHING_LOCATIONS`. You can put it back to 1. A few household cases are
still refused once, and a household whose address changes has moved; bloodhound's README
lists both under Ambiguous locations.

## What you need to do

```bash
composer require marque/bloodhound:^11.1.2 -W  # pulls threepio ^4.3
php artisan migrate                            # coming from bloodhound 10.0 (Marque 11.0)
```

Then read bloodhound's [Upgrading to 10.1](../../packages/bloodhound/README.md#upgrading-to-101)
and [Upgrading from 10.x to 11.0](../../packages/bloodhound/README.md#upgrading-from-10x-to-110),
and decide on `ambiguous_locations`. If you want staff told, listen for `CheatDetected`
with types `location_ambiguous` and `location_sharing_suspected`.

hound needs threepio lifted with it. Without `-W`, Composer keeps threepio at 4.1 and
quietly leaves hound at 5.1:

```bash
composer update marque/hound -W
```

# Marque 4.2 — 2026-09-01

## What changed

`marque/usarrs` now requires `laravel/fortify` and uses it to add two optional,
off-by-default login extras: **two-factor authentication** (TOTP — the six-digit
code from an authenticator app) and **passkeys** (WebAuthn — sign in with Touch ID,
Windows Hello, or a hardware security key instead of a password).

As a structural side effect, this release also closes a route collision:
previously, if your app had Fortify installed for any reason (every official
Laravel starter kit bundles it), Fortify's own `/login` and `/register` routes
could stay reachable underneath usarrs' own `auth_driver` restrictions —
`auth_driver=invite_only` correctly blocked usarrs' own registration page, but a
direct `POST /register` against Fortify's independently-registered route could
still create an account. usarrs now suppresses Fortify's routes unconditionally, so
there is exactly one front door regardless of what else is installed.

## Why

usarrs already owned the entire login/register/session/invites/admin surface —
nothing about auth was actually being left to "the host app" (that language in our
own docs was stale; corrected as part of this release, see below). Requiring
Fortify isn't usarrs taking on a new kind of responsibility — it's adding two more
auth *methods* to a surface it already fully owns, using Fortify's own
already-audited 2FA/WebAuthn code instead of hand-rolling TOTP and WebAuthn
ceremony from scratch.

The route-collision fix was the trigger: a site running `auth_driver=invite_only`
found, via direct testing rather than the UI, that Fortify's own registration route
was still live. The fix that closes that hole structurally — usarrs unconditionally
telling Fortify to never register its own routes — also happens to be the natural
foundation for offering 2FA/passkeys using Fortify's own code, so both shipped
together.

## Who's affected

Only sites using **`marque/usarrs`**. Both new features default off — upgrading
changes nothing about your users' experience unless you deliberately turn one on.

## What you need to do

**If you don't want 2FA or passkeys:** just upgrade. Nothing else changes.

1. Upgrade:
   ```bash
   composer require marque/usarrs:^6.0
   ```
2. Run the new migrations (two-factor columns + a passkeys table — both no-ops for
   existing users until the features are turned on):
   ```bash
   php artisan migrate
   ```
3. If you'd previously hand-written a workaround for the Fortify route collision
   (a `config/fortify.php` filter, or similar), you can remove it — usarrs now
   handles this itself, always.

**If you want to turn on 2FA and/or passkeys**, or if you're planning to replace
usarrs' auth UI with something fully custom, see the full technical checklist:
[Upgrading to Usarrs v6.0](../upgrade-guide-usarrs-v6.md).

## Packages affected

- `marque/usarrs` — v5.0.0 → v6.0.0

Nothing else in the suite changed in this release.

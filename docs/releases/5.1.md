# Marque 5.1 — 2026-09-04

## What changed

**The PHP floor drops from 8.4 to 8.3.** That is the whole release. Every package moves,
nothing else changes, and there is nothing to do on your side.

If you are running PHP 8.4, this changes nothing at all. If you are running a Laravel 13
app on PHP 8.3, you can now install Marque.

## Why

Marque required PHP 8.4 from [Marque 3.0](3.0.md) onward. Nothing in the code ever needed
it — no property hooks, no asymmetric visibility, none of the 8.4 array functions or the
new `mb_*` trims. It was a floor we chose rather than one anything imposed.

**Laravel 13 itself only requires `^8.3`.** So a working Laravel 13 application on PHP 8.3
was being turned away by Composer for no technical reason. For a project whose stated
purpose is to be usable by other people, that is a self-inflicted limit, and PHP 8.3 is
supported until December 2026.

The floor is now the same as the framework's.

## Who's affected

**Nobody negatively.** Lowering a floor cannot break an existing install: if your app is on
8.4, resolution is unchanged and you keep exactly what you had.

The people this is for are the ones who could not install Marque at all yesterday.

## What you need to do

Nothing beyond a normal upgrade:

```bash
composer update "marque/*"
```

No migration, no config change, no code change.

## One note for contributors

Marque's own test suite moved from **Pest 5 to Pest 4**, because Pest 5 requires PHP 8.4 —
which made the new floor impossible to actually test, and an untested floor is not a claim
worth making.

This affects nobody installing Marque: `require-dev` is not installed downstream. It only
matters if you are working on Marque itself, and the suite uses only `it`, `test`, `expect`,
`describe` and `beforeEach`, which behave identically in both versions.

The trade is deliberate. Pest 5's headline features — test impact analysis, the agent
browser plugin, built-in Rector, agent evals — are not used anywhere in the 905 tests, so
staying on 5 would have meant giving up a supported PHP version to keep features the project
does not use.

CI now runs the suite on both 8.3 and 8.4.

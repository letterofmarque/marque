# Marque 8.0 — 2026-10-06

**trove 4.5.0 · bloodhound 7.0.0 · hound 4.0.0 · guise 5.1.0 · disguise 5.1.0 · cennad 4.3.0**

## What's new

**Downloads finally carry the member's own announce URL.**

Until now, downloading a torrent handed the member the uploader's `.torrent` exactly as it
was uploaded, pointing at whatever tracker the uploader's client had written, or at none. On a
private tracker, members had to paste their own announce URL into their client by hand. The
code comments claimed otherwise.

Now every download is built for the person downloading it:

- **`announce`** is the installed tracker's URL for them. On bloodhound that's their own key,
  in the path or the query exactly as your `routes` config reads it. On hound it's the open URL.
- **`comment`** links back to the torrent's page on your site.
- **The info dictionary is the stored one, byte for byte**, so everyone shares one info hash
  and the uploader's original file seeds the same swarm.
- **Everything else the uploader's client wrote is dropped**, including `announce-list`
  (clients prefer it over `announce`, and it can carry the uploader's personal URL for another
  site). Cross-seeding will come back as its own package.

A member who has no announce key yet (for example, before verifying their address) gets a
clear refusal instead of a file their client can't announce with.

**Uploads have to match the tracker.** The `private` flag sits inside the info dictionary, so
it decides the info hash, and Marque never changes it for the uploader. Instead, each tracker
sets a rule, and an upload that breaks it is refused with instructions:

| | Default | Why |
|---|---|---|
| bloodhound | **require** private | Without the flag, clients share the swarm over DHT and peer exchange, outside the tracker |
| hound | **disallow** private | The flag turns off DHT and peer exchange, which a public swarm relies on |

Both can also be set to `warn_if_public`, `warn_if_private` or `allow`. BitTorrent v2-only
torrents, which have no v1 info hash, are refused everywhere; hybrids get a warning.

## Also fixed

- **Uploading a file that isn't a torrent crashed the page** in guise and disguise, and
  returned a 500 from the API. It's now a normal validation error on the file field.
- **An info "dictionary" that was really a list was accepted** and stored.

## Who's affected

**Anyone running bloodhound or hound.** Uploads that work today can be refused after the
upgrade: a public torrent on bloodhound, a private one on hound. Torrents already stored are
not re-checked.

guise, disguise and cennad change behaviour only in ways the tracker decides; with no tracker
installed, downloads are served exactly as before.

## What you need to do

Upgrade together. The frontends and the trackers all need trove 4.5:

```bash
composer require marque/trove:^4.5 marque/bloodhound:^7.0 marque/guise:^5.1
# or, for a public tracker:
composer require marque/trove:^4.5 marque/hound:^4.0 marque/disguise:^5.1
```

If you add cennad, require `marque/cennad:^4.3` in the same command.

**To keep the old upload behaviour**, set the rule to `allow` before upgrading:

```env
BLOODHOUND_PRIVATE_FLAG=allow   # or warn_if_public
HOUND_PRIVATE_FLAG=allow        # or warn_if_private
```

Nothing else is required. If your own code builds downloads or reads `.torrent` files, trove's
README ("Uploads and downloads") covers `TorrentFileService` and the new contract.

# Marque 7.0 — 2026-09-25

**trove 4.3.0 · bloodhound 6.0.0 · usarrs 8.0.0**

## What's new

**Tracker data has an owner.**

Until now, usarrs showed your ratio and announce key by reaching into your User model
for bloodhound's columns, first checking whether the right methods happened to exist,
across a dependency usarrs never declared. To make that work, bloodhound quietly made
those columns mass-assignable on *your* model.

Now trove declares the questions anyone may ask a tracker, bloodhound answers them, and
everything else asks instead of guessing:

```php
app(TrackerStatsInterface::class)->statsFor($user);        // uploaded, downloaded, seedtime, ratio
app(TrackerStatsInterface::class)->announceKeyFor($user);  // the key for the announce URL
```

On an install with no tracker, nothing answers, and pages that would have shown tracker
figures simply leave them out.

Announce keys move into a table bloodhound owns (`announce_keys`). Every existing key is
copied across, so **nobody needs to re-download a .torrent file.**

## Also fixed

- **Your users could set their own announce key and upload figure.** An ordinary
  `User::create($request->all())` accepted them, because bloodhound had added them to
  your model's `$fillable`. It no longer does.
- **Announce keys longer than 32 characters couldn't be stored** on MySQL, MariaDB or
  PostgreSQL, even though the key format is configurable for trackers migrating their
  existing keys. They now can.
- **On a User model with `$guarded = []`, bloodhound's trait silently broke `create()`**:
  `name`, `email` and the rest were dropped.
- **A user who had downloaded nothing saw a blank ratio.** It now shows ∞.

## Who's affected

**Anyone running bloodhound** — the private tracker. usarrs users without bloodhound only
need the version bump.

**The one thing that will bite you:** if your app reads `$user->announce_key` (to build
an announce URL, say), it keeps *appearing* to work. It returns the key as of the
upgrade, and it goes quietly wrong the first time a user regenerates. Switch it to
`announceKeyFor()`.

## What you need to do

Upgrade all three **in one command** — bloodhound 6 refuses to install beside usarrs 7:

```bash
composer require marque/trove:^4.3 marque/bloodhound:^6.0 marque/usarrs:^8.0
php artisan migrate
```

Then follow the [bloodhound v6 / usarrs v8 guide](../upgrade-guide-bloodhound-v6-usarrs-v8.md)
for the code changes: reading keys, the removed trait methods, and published usarrs views.

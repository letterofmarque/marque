# Marque 11.0 — 2026-10-28

**trove 5.0.0 · usarrs 9.0.0 · bloodhound 10.0.0 · parley 4.0.0 · taxonomy 2.0.0 ·
marque 2.0.0 · bosun 1.0.0 (new) · cennad 4.5.0 · deck 2.2.0 · disguise 5.4.0 ·
guise 5.4.0 · hound 5.1.0 · skipper 1.1.0 · squidink 1.1.4**

## What's new

**The tracker has an owner.** A new role sits above Admin. Only the owner grants or removes
Admin, so admins can no longer demote or ban each other, or the owner. Nobody changes their
own role or bans themselves, and the last owner can't be demoted. Everywhere else an owner
is an admin: every "admins may" check lets them in.

**Every staff action is recorded.** A ban, a role change, a torrent edited or deleted by
someone who isn't its uploader, a thread locked, a post removed, an exemption granted, a
seedbox approved, a term added to the catalogue: each package records who did it, to what,
why and what changed. A member editing their own torrent isn't a staff action, and neither
is automatic enforcement.

**bosun, a new package, keeps and shows them.** Install `marque/bosun` and the owner gets:

- **a Staff screen:** the staff by role, how many staff actions each took over the last
  7, 30 and 90 days, when each was last on the site, and role changes that need a reason
  and follow the owner rules;
- **an Audit log:** every staff action, filterable by staff member, action, subject and date.

Without bosun the records go nowhere and nothing else changes. If a record can't be stored,
the staff action still happens and the gap is logged.

**Bans now ban on a stock Laravel app.** Before usarrs 9.0, banning or unbanning a member or
changing their role from the admin screen silently did nothing on an app whose `User`
model kept Laravel's default fillable list: `role` and `status` aren't on it. The screen said
it was done. It now saves whatever the model allows. Apps that call `Model::unguard()` were
never affected.

**The installer can be answered from a file.** `marque:install --preseed=marque.yml`, in the
spirit of Debian's preseeding, answers its questions from YAML. That makes an install
repeatable and lets it run unattended (`--no-interaction`) in CI. It's strict: a misspelt
key refuses the file rather than becoming a default nobody chose. The account the installer
creates is now the owner, and it offers bosun.

**Also:**
- taxonomy's admin edits move into a `Curator` service so they're recorded wherever
  they're made.
- deck draws the admin panel's and dashboard's icons, which used to render blank.
- `bloodhound:standing` requires `--by`, as 9.x warned it would.

## Who's affected

**Everyone who upgrades.** Nobody is the owner after the upgrade, and until someone is, no
one can grant or remove Admin. Run `usarrs:owner` once (below).

**Anyone whose app code compares roles.** A `match` on trove's `Role` meets a new case,
`Owner`. `isAdmin()` now means admin or above, so code that meant "exactly Admin" has to
compare the role itself.

**Anyone with a hand-written user model, or their own implementation of trove's or usarrs'
interfaces.** Those interfaces gained methods or parameters:
- `UserInterface` gains `isOwner()`;
- `TorrentServiceInterface` and `InviteServiceInterface` take an optional actor and reason;
- so do parley's service interfaces.

A model using `HasRoles`, or code that only calls these services, needs nothing.

**Anyone who scripts exemptions.** `bloodhound:standing exempt` and `unexempt` need
`--by=<admin id>`.

**Admins.** They can no longer change, ban or unban another admin or the owner, or revoke
their invites. That's the owner's job now.

**Anyone running a stock `User` model.** Bans and role changes start working. Check whether
anyone you "banned" before was actually banned.

## What you need to do

Every package that depends on trove moves together. Widen your constraints and update:

```bash
composer require marque/trove:^5.0 marque/usarrs:^9.0 -W
# and whichever of these you run:
#   marque/bloodhound:^10.0  marque/parley:^4.0  marque/taxonomy:^2.0
#   marque/guise:^5.4  marque/disguise:^5.4  marque/cennad:^4.5
#   marque/hound:^5.1  marque/skipper:^1.1  marque/deck:^2.2
php artisan migrate
```

Then make yourself the owner:

```bash
php artisan usarrs:owner you@example.com
```

Then, if you want the record and the screens:

```bash
composer require marque/bosun
php artisan migrate
```

bosun's screens appear under **Staff** in the admin panel (skipper). It supports integer
user ids.

Search your app for `match (` on a role and for `isAdmin()` used to mean "exactly Admin".
If you script exemptions, add `--by`. bloodhound's
[Upgrading from 9.x to 10.0](../../packages/bloodhound/README.md#upgrading-from-9x-to-100)
has the detail.

# Marque 5.0 — 2026-09-03

## What changed

**Ratio accounting is now durable and auditable.** Before this release, a user's
uploaded and downloaded totals were accumulators with nothing behind them — if a number
went wrong, it stayed wrong, and nothing anywhere could tell you it had. This release
makes the announce log the source of truth, and adds the commands that detect and repair
drift.

Two other things ship alongside it, both closing holes found while the ledger work was
underway: **per-torrent access control** in trove, and **the API's read endpoints now
require authentication by default** in cennad.

## Why

### The ratio problem

Bloodhound computed each announce's byte deltas against a baseline held only in Redis,
then handed the result to a queued job. Two failure modes fell out of that:

- **A lost job was a lost credit, permanently.** Redis had already advanced the baseline
  by the time the job ran, so the bytes could never be recomputed. And because bloodhound
  requires Redis, most deployments point the queue at that same instance — one restart
  could take both halves at once.
- **Nothing could detect it.** `users.uploaded` was a running total with no durable record
  behind it. There was no second source to compare against, so a wrong ratio was
  indistinguishable from a right one.

Ratio is what gets people banned. A number that can be silently wrong, with no way to
check it and no way to rebuild it, is the wrong shape for that job.

Now: `announce_log` is written **synchronously** on the announce path (0.5ms), carrying
`prior_up`/`prior_down` — the baseline each delta was computed against — so every credit
carries its own arithmetic proof. Totals are a projection folded from the ledger by a
watermark cursor. `bloodhound:reconcile-ledger` compares them daily and reports drift
loudly; `bloodhound:rebuild-totals` recomputes them from scratch; `bloodhound:audit-ledger`
checks the ledger's own coherence, including the per-peer baseline chain, where a break is
what a past Redis outage looks like.

A Redis miss now recovers the peer's last counters from the ledger instead of crediting
zero. A total Redis loss costs latency, not bytes.

### The access-control gap

Trove had no way to restrict a torrent to a subset of users, and guise's torrent detail
page and `.torrent` download performed **no authorization at all**. The download matters
most — a `.torrent` carries the user's announce key.

Trove now has `min_role` on torrents (null by default, so nothing is hidden by upgrading),
a policy gating detail pages and downloads, and — the load-bearing half — a
`visibleTo()` scope filtering listings, because a policy guards one record and would leave
restricted torrents sitting in every index, API collection and count.

### The API default

Cennad's `index` and `show` were open to unauthenticated requests while the package's own
README stated that all endpoints require authentication. The documentation described the
intent; the code shipped the opposite. Cennad can't tell whether it's serving a private
tracker or a public one, so it now defaults to the private assumption.

Anyone running a private tracker who installed cennad alongside guise and assumed guise's
auth gate covered the API was exposing their full catalogue to anyone who could reach the
endpoint.

## Who's affected

**Everyone**, but not equally.

- **Running bloodhound?** This is the big one. Read "What you need to do" in full — there's
  a migration that carries your existing totals in, and a config default that flips.
- **Running cennad?** Your API reads may close or may not, depending on whether you ever
  published the config. This is the trap in this release — see below.
- **Running guise or disguise?** You gain access control you didn't have. Nothing breaks.
- **Running only usarrs or parley?** Constraint widening only. Nothing behaves differently.

## What you need to do

### Everyone: upgrade the suite in one go

Trove goes to 4.0, so every Marque package you use moves together:

```bash
composer require marque/trove:^4.0 marque/bloodhound:^5.0 marque/threepio:^3.1 \
  marque/guise:^4.1 marque/cennad:^4.0 marque/usarrs:^6.1 --with-all-dependencies
```

Adjust the list to the packages you actually have. Then:

```bash
php artisan migrate
```

### Bloodhound: check the config default that flipped

**`announce_log.enabled` now defaults to `true`.** A source of truth can't be opt-in — an
install without it has no way to know its ratios are wrong. If you published
`config/bloodhound.php` and it says `false`, you are opting out of the durability this
release exists to provide.

The migration carries each user's pre-ledger totals in as an `opening_balance` ledger row
and folds it immediately, so reconciliation starts clean rather than reporting every user's
entire history as drift. **That row asserts your old total was correct as of migration; it
is not evidence that it ever was.** If you have reason to think a user's ratio was already
wrong, this release gives you the tools to investigate it, but it cannot retroactively fix
history that was never recorded.

Per-torrent history starts empty — it was never recorded before now — so hit-and-run
enforcement only means anything for torrents grabbed after the upgrade.

The `snatches` table is absorbed into `torrent_user`; existing rows are carried over.
`queue.*` config is no longer read and will be removed in the next major.

### Cennad: the untouched-config trap

`public_middleware` and `protected_middleware` are renamed to `read_middleware` and
`write_middleware`. The old names are still honoured and **take precedence** — because
Laravel merges package defaults into every published config, the presence of
`read_middleware` proves nothing, while an old key can only be there because someone set it
deliberately.

**This means an untouched 3.x published config keeps its open reads.** If you published
`config/cennad.php` on 3.x and never edited it, upgrading alone does not close your API.
You'll get an `E_USER_DEPRECATED` notice telling you so. Rename the keys to adopt the new
default:

- `public_middleware` → `read_middleware`
- `protected_middleware` → `write_middleware`

If you never published the config, reads now require authentication and there's nothing to
do.

**Running a public tracker** (hound/disguise) and want the catalogue readable by guests?
Publish the config and drop the guard from reads only:

```php
'read_middleware' => ['api'],
```

Leave `write_middleware` alone — uploads, edits and deletes stay governed by trove's
`TorrentPolicy` on top of whatever middleware you set.

### Optional: dead-torrent filtering

`trove.hide_dead_torrents` (default **false**) hides seederless torrents from listings.
It's off by default because a torrent has no seeders until its first announce, so turning
it on immediately after upgrading would hide every fresh upload and empty a catalogue
that hasn't had an announce cycle yet. Turn it on once your swarm counts have populated.

## Packages affected

- `marque/trove` — v3.0.0 → **v4.0.0** (`TorrentServiceInterface` signatures, `min_role`, swarm counts)
- `marque/bloodhound` — v4.1.0 → **v5.0.0** (the ledger, `snatches` absorbed, `announce_log.enabled` default)
- `marque/cennad` — v3.0.0 → **v4.0.0** (reads require auth, middleware config keys renamed)
- `marque/threepio` — v3.0.0 → v3.1.0 (baseline hook, expired-peer recursion fix)
- `marque/guise` — v4.0.0 → v4.1.0 (authorization on detail pages and downloads, swarm columns)
- `marque/disguise` — v4.0.0 → v4.1.0 (guest authorization, swarm columns)
- `marque/hound` — v3.0.0 → v3.1.0 (swarm counts on the announce path)
- `marque/usarrs` — v6.1.0 → v6.1.1 (trove constraint widened; no functional change)
- `marque/parley` — v2.1.0 → v2.1.1 (trove constraint widened; no functional change)

`marque/ise` and `marque/squidink` are unchanged.

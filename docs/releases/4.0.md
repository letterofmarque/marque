# Marque 4.0 — 2026-08-20

## What's new

- **`marque/squidink`** (new package) — turns plain Markdown or BBCode text
  into safe HTML. If you want rich text anywhere (torrent descriptions,
  forum posts, comments), this is what renders it.
- **`marque/parley`** (new package) — threaded discussion. Comments on
  torrents, plus an optional lightweight forum. Built on top of squidink for
  the actual text formatting.

Both are optional — install them only if you want rich text or discussion
features. Nothing else requires them.

## What changed

**`marque/id` was renamed to `marque/ise`.** Same package, same purpose (the
shared app layout shell — navigation, theming, layout components), just a
new name. The old name (`id`) was a pun that stopped making sense once
`marque/usarrs` (which actually handles user identity/auth) existed
alongside it — the two names read as if both were about user identity, when
`id`/`ise` has never had anything to do with auth. It's pure UI shell.

`marque/id` still exists on Packagist but is marked abandoned, pointing at
`marque/ise`. It will keep working for now, but won't get further updates.

## Who's affected

Anyone using `marque/guise`, `marque/usarrs`, or `marque/disguise` — they
all depend on the layout shell package, so the rename ripples through them.
If you only use `marque/trove`, `marque/bloodhound`, `marque/threepio`, or
`marque/cennad` directly (no web frontend), this doesn't affect you.

## What you need to do

1. Swap the dependency:
   ```bash
   composer remove marque/id
   composer require marque/ise:^1.0
   ```
2. If you published `id`'s config or views (`--tag=id-config`,
   `--tag=id-views`), re-publish under the new names
   (`--tag=ise-config`, `--tag=ise-views`) and remove the old published
   files.
3. If your app references `id::` view namespaces or `Marque\Id\...` classes
   directly anywhere, update them to `ise::` / `Marque\Ise\...`.
4. Bump the frontend packages that depend on it:
   ```bash
   composer require marque/guise:^4.0 marque/usarrs:^4.0 marque/disguise:^4.0
   ```

If you're not ready to migrate off `id` yet, you can stay on the old
`marque/guise:^3.0` / `marque/usarrs:^3.0` / `marque/disguise:^3.0` line —
they still depend on `marque/id`, which still works. There's no forcing
function to move immediately, but new features will land on the `ise`-based
line going forward.

## Packages affected

- `marque/id` → superseded by `marque/ise` v1.0.0 (new package name)
- `marque/guise`, `marque/usarrs`, `marque/disguise` — bumped major (now
  depend on `ise`, not `id`)
- `marque/squidink` — new, v1.0.0
- `marque/parley` — new, v1.0.0 (bumped to v2.0.0 in this same window to
  pick up the `ise` dependency)

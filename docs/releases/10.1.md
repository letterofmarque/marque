# Marque 10.1 — 2026-10-22

**bloodhound 9.1.0 · trove 4.9.0 · usarrs 8.6.0 · marque 1.2.0**

## What's new

**Hit-and-run.** This is the rule most private trackers run beside a ratio: a member who
downloads a torrent owes it some seeding.

- **The obligation.** A torrent a member downloaded more than 10% of is owed **72 hours**
  of seeding, or a **1:1 ratio** on it, whichever comes first.
- **Warnings and strikes.** Away from it a day while short, they're pre-warned. Away three
  days, it's a strike. A strike lapses after 14 days, and seeding the torrent to the
  requirement clears it sooner.
- **Three active strikes pause new downloading**, exactly as a lapsed ratio watch does.
  Seeding never is.

The mechanics are UNIT3D's, the closest thing open-source trackers have to a standard.
The 72 hours replaces UNIT3D's 7 days, because 72 hours is the commonest figure trackers
publish and Marque counts seedtime conservatively. Every number is configurable.

**It's off for an existing tracker, and on for a new one.** Upgrading changes nothing until
you set `BLOODHOUND_HIT_AND_RUN=true`. `marque:install` turns it on for a private tracker it
builds from scratch. Switched on, it counts only torrents first active from then, so it
never strikes a member's history. `ratio_mode=seedtime` runs it without the ratio rule.

**Members see what they owe.** `/profile/stats` lists each torrent a member still owes
seeding on, with how far along they are, plus any strikes and when they lapse. The
dashboard shows the count.

## Who's affected

Nobody's tracker changes on upgrade. Hit-and-run is off until you turn it on.

## What you need to do

```bash
composer require marque/bloodhound:^9.1 marque/trove:^4.9 marque/usarrs:^8.6 -W
php artisan migrate
```

**To turn hit-and-run on:** set `BLOODHOUND_HIT_AND_RUN=true`. Tell your members first, and
check the numbers in bloodhound's README ("Hit-and-run"). It needs the scheduler, like the
ratio rule.

**If you published `config/bloodhound.php`:** the new `hit_and_run` block merges in on its
own, because it's a top-level key. `min_seedtime` was never read before. If your published
file still has the old 86400 (24 hours), that is now what's enforced, so change it if you
meant 72 hours.

If you published usarrs' views, re-publish `profile/stats.blade.php` and
`dashboard/panels/tracker-stats.blade.php`.

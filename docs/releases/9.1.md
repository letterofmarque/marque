# Marque 9.1 — 2026-10-21

**usarrs 8.4.0 · bloodhound 8.1.0 · trove 4.7.0 · threepio 4.1.0 · deck 2.0.1**

Everything here came from one real upgrade: a private tracker going from Marque 6.0 to
9.0 in one jump. Each item is something that broke, or went quiet, where it shouldn't
have. All of it is backward compatible.

## What's new

**An app with its own `/dashboard` no longer breaks every page.** Laravel's starter kits
ship `Route::get('dashboard', ...)->name('dashboard')`. Your app's routes load after
usarrs', so yours replaced its dashboard and took the name `dashboard.index` with it.
deck's navigation then threw `RouteNotFoundException` on every page that showed it, and
nothing said why. Now:

- deck 2.0.1 leaves out a nav entry whose route doesn't exist;
- usarrs logs an error once a day naming the route that took the path;
- `usarrs.dashboard.path` (`USARRS_DASHBOARD_PATH`) moves usarrs' dashboard if you want to
  keep yours.

**A stale published config is reported.** A `config/bloodhound.php` published before 2.0
still sets the protocol settings that moved to threepio then, under their old
`BLOODHOUND_*` env vars. Those have been ignored ever since, and nothing said so: a tracker
configured for a 900-second minimum interval was running on threepio's 300. bloodhound now
logs a warning once a day for each key it no longer reads. A moved key's warning gives the
value you set and the value in effect. The keys that moved to threepio are in the table
below; the retired `logging` and `queue` blocks are reported too.

**Login goes back where the user was going.** Every login used to land on `/`. Now it
returns to the page the user was sent to log in from, across a two-factor challenge too.
Otherwise it goes to `usarrs.home` (`USARRS_HOME`, default `/`). Set that to `/dashboard`
if your `/` is a splash page. It's not only the login form: registration, magic links,
OAuth sign-in, an emailed OAuth connection link, the two-factor challenge and passkeys all
land there too, and so does password confirmation when nothing asked for it. Connecting a
provider while already signed in still returns to the profile page. A test expecting `/`
after any of the others needs updating if you set it.

**Every member can get an announce key.** A key was issued at sign-up, or when the
`Verified` event fired. So a user verified by setting `email_verified_at` directly (an
admin screen, a seeder), or inserted without Eloquent (an import), never got one. Now:

- the first case is issued a key on save;
- `php artisan bloodhound:issue-keys` covers the second (run it after an import, with
  `--dry-run` to count first);
- the dashboard's Announce Key panel shows even with no key, offering Generate, or telling
  an unverified member to verify.

**A tracker with no scheduler says so.** Totals move only when
`bloodhound:aggregate-ledger` folds the ledger, every minute on the scheduler. Without
`schedule:run`, nobody is credited for anything. A scheduled check can't report a
scheduler that isn't running, so announces check: at most every five minutes, if the
oldest unfolded row is more than ten minutes old, an error is logged naming the
scheduler.

**Seed time and leech time on the dashboard**, beside the byte counts. trove's
`TrackerStats` now carries `leechtime`.

**Building valid torrents in your tests.** Since 8.0, uploads are checked against the
private-flag rule and downloads parse the stored file, so fixtures like
`'fake torrent content'` fail. threepio 4.1's `Testing\FakeTorrent` builds a real one:

```php
use Marque\Threepio\Testing\FakeTorrent;

$torrent = FakeTorrent::make();        // private, with a distinct info_hash each time
$torrent->upload();                    // an UploadedFile for a form or API test
$torrent->infoHash();                  // what trove stores it under
```

**A panel for verified members only.** The dashboard admits unverified members, because
the Announce Key panel tells them to verify, while guise's torrent routes need `verified`.
trove's `DashboardPanel::verifiedOnly()` gates a panel the same way those routes do.

**Optional: a malformed announce key gets a reason, not a 404.** With the key in the path,
a malformed one was the app's HTML 404, which clients show as a garbled error. Set
`BLOODHOUND_MALFORMED_KEY=failure` to answer it with a bencoded `Invalid announce key`.
That becomes the default in bloodhound 9.0. Through 8.x it stays opt-in, because the 404
was documented behaviour. With a published `config/bloodhound.php`, add
`'malformed_key' => env('BLOODHOUND_MALFORMED_KEY', 'not_found'),` to its `routes` block
first: a published block replaces the shipped one whole, so the env var does nothing until
the key is there.

## Also fixed

- The announce key and its Regenerate button no longer overflow a narrow dashboard card.

## Who's affected

**Anyone whose app has its own `/dashboard`.** Check your log after upgrading. If usarrs
reports a collision, take one of the two ways out below.

**Anyone running bloodhound with a config published before 2.0.** Check your log for the
warnings and move the settings to `config/threepio.php` or the `THREEPIO_*` env vars:

| Old (ignored since bloodhound 2.0.0) | Now |
|---|---|
| `BLOODHOUND_ANNOUNCE_INTERVAL` | `THREEPIO_ANNOUNCE_INTERVAL` |
| `BLOODHOUND_MIN_ANNOUNCE_INTERVAL` | `THREEPIO_MIN_ANNOUNCE_INTERVAL` |
| `BLOODHOUND_MAX_PEERS` | `THREEPIO_MAX_PEERS` |
| `BLOODHOUND_PEER_EXPIRY` | `THREEPIO_PEER_EXPIRY` |
| `BLOODHOUND_REDIS_CONNECTION` | `THREEPIO_REDIS_CONNECTION` |
| `BLOODHOUND_REDIS_PREFIX` | `THREEPIO_REDIS_PREFIX` (default `marque:`) |

Note the prefix. If you set `BLOODHOUND_REDIS_PREFIX` and it has been ignored, your peers
have been under `marque:` all along, so don't move them when you change the variable.

**Anyone who imported members.** Run `bloodhound:issue-keys`.

**Nobody else needs to do anything.** Login now honours the intended page, which is
Laravel's own behaviour and what most apps expected.

## What you need to do

```bash
composer require marque/usarrs:^8.4 marque/bloodhound:^8.1 marque/trove:^4.7 -W
```

bloodhound 8.1 and usarrs 8.4 need trove 4.7, and deck and threepio follow along. Then:

1. **Your own `/dashboard`?** Either delete your route and move what it showed into
   dashboard panels (trove's README, "Dashboard panels"; `verifiedOnly()` for anything
   your `verified` routes guard), or set `USARRS_DASHBOARD_PATH=home` to move usarrs'.
2. **Splash page at `/`?** Set `USARRS_HOME=/dashboard`.
3. **A published `config/bloodhound.php`?** Check the log for warnings, and move the
   settings named.
4. **Imported members?** `php artisan bloodhound:issue-keys --dry-run`, then without
   `--dry-run`.
5. **Optional:** `BLOODHOUND_MALFORMED_KEY=failure`, after adding `malformed_key` to the
   `routes` block of a published `config/bloodhound.php`.

If you published usarrs' views, re-publish `partials/tracker-figures.blade.php` and
`partials/announce-key.blade.php` to get seed and leech time and the wrapping key row.
